Result: fonts and images use almost half of the flash content. Fonts and sprites use 845,873 bytes, 45.9% of the flash content. The 16 px Chinese font is the largest. It must show any answer from the phone, so it has GB2312 level 1. The Heygo app code is only approximately 54 KB.

The BLE controller and stack also allocate heap memory at runtime. A device measurement is necessary for that part. This page does not show it.

LVGL pool: 28 KiB

CONFIG_LV_MEM_SIZE_KILOBYTES=28 (sdkconfig.defaults). After the management overhead, 25,752 bytes are available.

Why the pool changed from 24 KiB to 28 KiB. With the page rail (D-33), the 24 KiB pool stopped the live data page when it drew the speed digits. The largest free block was then only 1,936 bytes. The pool is now 28 KiB, and it uses 4 KiB more system RAM (需求文件夹/02-architecture.md:334 and 05-decision-amendments.md). The build agrees: the LVGL .bss changed from 25,084 to 29,180 bytes, exactly 4,096 bytes more.

These numbers come from a 64-bit host. A host pointer has 8 bytes. An ESP32-C3 pointer has 4 bytes. Thus, the device uses less pool memory. The pool is small, so the firmware keeps only one screen at a time.

At each page change, the device logs the pool use, the largest free block, and the free system heap. The device memory test reads these lines (02-architecture.md:335).

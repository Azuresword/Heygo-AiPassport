# Sprint 0：4 小时计划

版本：0.5。日期：2026-10-16。状态：提案。

## 1. Sprint 目标

为一次教练提问做出设备逻辑，并在主机上测试通过。

开发板不在手边，手机应用也还没有遵循 07 号文档的版本。
所以 Sprint 0 只在主机上进行，由桩程序扮演手机。

## 2. 时间盒

Sprint 0 共 4 小时开发时间。
团队没有速度数据。下面的分钟数是计划上限，不是实测值。

| 顺序 | 任务 | 故事 | 时间盒 | 完成检查 |
| --- | --- | --- | --- | --- |
| 1 | T-1 模式与音频状态机 | US-17、US-06、US-07 | 60 分钟 | 生成的转移表，每条转移各有一项主机测试。 |
| 2 | T-2 P0 消息的包层 | US-01、US-06、US-07 | 75 分钟 | 主机测试覆盖组包、解包、`xid` 和错误码。 |
| 3 | T-3 IMA ADPCM 编码器和解码器 | US-06、US-07 | 60 分钟 | 主机测试覆盖块大小、往返、丢块和满幅输入。 |
| 4 | T-4 门禁与构建 | 无 | 45 分钟 | 静态门禁和固件构建通过。报告中写明静态 RAM。 |
| | 合计 | | 240 分钟 | |

**砍线。** 如果 T-1 和 T-2 加起来超过 150 分钟，就去掉 T-3。
07 号文档的裸 PCM 回退能让链路在没有 ADPCM 时照样可测。
T-4 无论如何都要做。

## 3. 任务细节

### T-1：模式与音频状态机（60 分钟）

使用固件工作区中现有的流程生成器，替换旧的语音流程图。
状态覆盖滑行模式、休息模式，以及音频所有者 None、AgentCapture 和 AgentPlayback。

主机测试必须覆盖以下路径：

1. 在滑行模式中长按 OK 进入休息模式。这次按键绝不启动采集。
2. 在教练页重新长按 OK 开始采集。
3. 松键结束提问。达到 20 秒上限也结束提问。
4. 长按 UP 取消采集，也取消播放。
5. 播放期间长按 OK，先停止播放，再开始采集。
6. 长按 DOWN 再短按 OK，返回滑行模式并停止所有音频。
7. 链路中断时停止采集和播放。
8. 满 3 块、收到 PLAY_END、第一块到达后 60 ms，三者先到者触发开始播放。

### T-2：包层（75 分钟）

用纯 C 编写，不依赖 NimBLE、ESP-IDF 或 LVGL。
覆盖 07 号文档中的 P0 消息：HELLO、HELLO_ACK、PHONE_STATUS、DEVICE_STATUS、ERROR、CONTEXT、AGENT_START、AGENT_END、AGENT_CANCEL、AGENT_STATE、AUDIO_UP、AUDIO_DOWN、PLAY_START 和 PLAY_END。

主机测试必须证明以下规则：

- 每种消息组包后再解包，字段保持一致。
- 长度错误得到错误码 2。未知类型得到错误码 1。
- 解析器忽略载荷末尾多出的字节。
- HELLO 携带主版本 0、次版本 1。手机给出不同的次版本时，得到错误码 3。
- 未知的编码值得到错误码 7。
- `xid` 过期的音频块或状态包，设备一律丢弃。

### T-3：IMA ADPCM 编解码器（60 分钟）

用纯 C 编写，使用 07 号文档第 7 节的块格式。

主机测试必须证明以下规则：

- 一块 320 个采样编码后正好 164 字节。
- 不满一块的最后一块补静音后，编码结果仍是 164 字节。
- 解码后的 1 kHz 正弦波信噪比高于 20 dB。这个阈值是初始值。
- 丢失一块之后，解码器能正确读取下一块。
- 满幅输入不会造成整数溢出。

### T-4：门禁与构建（45 分钟）

把三组测试加入仓库门禁。
运行静态门禁和固件构建。
从构建 map 中记录静态 RAM。

## 4. Sprint 0 的完成定义

- 主机测试通过。
- 静态门禁通过。
- 固件构建通过。
- 报告写明静态 RAM。

Sprint 0 不关闭任何故事。每个 P0 故事仍需要设备测试和真实的手机应用。

```text
Build: PASS / FAIL / NOT RUN
Host tests: PASS / FAIL / NOT RUN
Device tests: NOT RUN
Unverified: 真实的手机应用、全部设备行为、全部现场条件
```

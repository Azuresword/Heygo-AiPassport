# HeygoAI 与 AI Passport：产品需求

版本：0.6。日期：2026-10-17。状态：评审草案。
产品负责人尚未指定。
本文定义项目概念，不代表联动功能已经实现。

## 1. 产品目标

滑雪者滑行时在设备上看实时数据，休息时向 AI 教练提问并听到回答。
滑雪者不用拿出手机，也不用摘手套。

HeygoAI 通过待确认的接口提供滑雪分析和教练能力。
手机应用负责语音识别、语音合成、滑行数据和与 HeygoAI 的连接。
AI Passport 提供按键、麦克风、喇叭和一块小屏幕。

使用时手机留在口袋里。设备通过手机连网。
所以设备省掉的是"把手机拿出来"，不是手机本身。

## 2. 用户与使用时机

| 用户 | 需求 | 使用时机 |
| --- | --- | --- |
| 休闲滑雪者 | 不看手机，也知道这一趟滑了多少。 | 滑行中。 |
| 休闲滑雪者 | 不看手机长报告，也知道这一趟的问题和下一趟怎么改。 | 一趟滑完后，坐缆车或休息时。 |
| 正在练习技能的滑雪者 | 下一趟之前得到一条简短建议。 | 下一趟开始前。 |
| 项目测试者 | 复现一次失败的提问或一次错误的数据显示。 | 室内测试时。 |

试用阶段面向成年人和小范围群组。
试用使用现有开发板，不需要新电路板或新外壳。

## 3. 产品流程

1. 用户用现有手机应用连接设备。
2. 设备开机后进入滑行模式。滑行页显示手机发来的实时数据。
3. 用户长按 OK 进入休息模式。休息模式打开后停在教练页。
4. 用户再次长按 OK，提出问题。
5. 用户松开 OK，设备结束本次提问。
6. Agent 用语音回答，屏幕上显示简短文字。
7. 用户可以长按 UP 停止回答。
8. 教练页空闲时，用户短按 DOWN 打开报告页，查看上一趟的报告。短按 UP 回到教练页。
9. 下一趟开始前，用户长按 DOWN，再短按 OK，返回滑行模式。

休息模式表示用户主动确认自己已经停下。
设备无法检查运动状态。休息模式绝不声称周围环境安全。

## 4. 范围与优先级

D-17、D-18 和 D-22 规定了以下优先级。理由见[决策修订](05-decision-amendments.zh_CN.md)。

| 优先级 | 增量 | 需求 |
| --- | --- | --- |
| P0 | 增量 1：教练语音链路 | REQ-01、REQ-06、REQ-07、REQ-08、REQ-15、REQ-17、REQ-20 |
| P1 | 增量 2：实时数据与报告 | REQ-02、REQ-03、REQ-21 |
| P1 | 增量 2 之后 | REQ-04、REQ-09、REQ-13 |
| P2 | 后续候选 | REQ-10、REQ-11、REQ-12、REQ-18、REQ-19 |
| 延后 | 不在任何已计划的增量里 | REQ-05、REQ-14、REQ-16 |

增量 1 完整打通一次语音链路：按键、蓝牙链路、手机、Agent、手机、蓝牙链路、喇叭。
增量 2 复用同一条蓝牙链路，方向只有手机到设备。
D-22 让增量 2 与增量 1 的设备验收并行开发。两个增量各自验收。

### 首版不包含的内容

- 指标图表、离线报告缓存、弯型视图和真人对讲。它们在增量 2 之后或延后。
- 自动事故检测或救援调度。
- 认证教学、医疗建议或防伤保证。
- 由设备自己测量速度、位置、立刃角或身体姿态。
- 速度排名、速度徽章或任何奖励高速的内容。
- 默认持续监听、唤醒词或常开麦克风。
- 不经手机的无线电对讲。
- 新硬件、量产、支付或公开社交网络。
- 蓝牙加密、配对码或绑定校验。
- 隐私与授权功能。
- 功耗管理，包括休眠模式和低功耗链路参数。

## 5. 能力边界

| 项目 | 证据或状态 | 对产品的影响 |
| --- | --- | --- |
| 屏幕 | 240 × 320。没有证据支持触摸。 | 显示状态、简短文字和少量数字。 |
| 按键 | UP、DOWN、OK 共用一个 ADC 输入。 | 每次只用一个按键。 |
| 音频 | 有麦克风、喇叭和 PCM 接口。没有回声消除。 | 用小块把声音流式发给手机。绝不边录边放。 |
| 资源 | ESP32-C3、8 MB Flash、无 PSRAM。 | 语音识别、语音合成、Agent 和数据计算都不放在设备上。 |
| 电源 | 500 mAh 电池。 | D-18 把功耗管理推迟。不声称任何续航。 |
| 运动与位置 | 没有证据表明设备有 IMU、GNSS 或气压计。 | 所有滑行数据都由手机计算，设备只负责显示。 |
| HeygoAI | 还没有 API 契约和样例数据。 | 由手机应用负责集成。 |
| 手机应用 | 已经存在，由另一个团队开发。 | D-23 规定：设备团队定义数据字段，手机应用团队按字段适配。[蓝牙协议草案](07-ble-protocol-draft.zh_CN.md)给出包格式。 |

## 7. 体验细节

### 教练页

教练页始终显示接收对象：AI 教练。
页面每次只显示一种状态：就绪、正在听、思考中、回答中或失败。
每种状态都同时使用文字和图标，绝不只靠颜色表达。

长按 OK 500 ms 开始采集。设备立即把每一块声音流式发给手机。
设备不等待网关。手机保存问题，直到网关接受。
用户松开 OK 后，设备停止采集，并告诉手机问题已结束。
单个问题最长 20 秒。

手机把回答逐块流式发回设备。设备每收到一块就播放一块。
屏幕可以显示简短的转写或简短的回答。
识别失败时，屏幕请用户重说。
设备不提供转写编辑，因为三个按键无法编辑文字。

### 取消与退出

长按 UP 500 ms，取消当前的采集或播放。
该命令之后 200 ms 内停止播放，100 ms 内停止采集。
从最初按下 UP 到停止出声，总目标为 700 ms。
长按 DOWN 500 ms 弹出退出确认，再短按 OK 返回滑行模式。
长按之后不会再触发短按。

### 音频规则

设备绝不同时录音和播放。
播放期间长按 OK，先停止播放，然后才开启麦克风。
链路中断时，设备停止采集并显示故障。
已取消的回答绝不恢复。

### 滑行页

D-21 让滑行页显示实时数据。滑行时视线应该在雪道上，所以页面只放 5 个数字，最大的一个是速度。

| 区域 | 内容 | 示例 |
| --- | --- | --- |
| 标题 | 今日第几趟和本趟滑行时间 | 第 4 趟 · 02:31 |
| 主数字 | 当前速度 | 38 km/h |
| 副数字 | 落差、滑行距离和转弯数 | 落差 312 m · 1.8 km · 24 弯 |
| 按键提示 | 不变 | 长按 OK 进入休息 |

- 手机判定开始滑行后，每 1 秒发一帧。设备收到一帧就更新一次。
- 5 秒没有收到新帧，速度显示"--"，其他数字保留，并标明数据过期。
- 还没有任何数据时，正文显示"等待手机数据"。
- 速度只显示数字，不用颜色、动画或提示音强调高速。
- 手机没有速度时，发送未知值，屏幕显示"--"。

### 每趟报告

D-26 规定：每一趟结束后，手机发送这一趟的报告。D-27 规定报告显示在两个地方：

- **缆车上的滑行页。** 一趟结束后，滑行页显示这一趟的 Heygo IQ、核心问题和小建议，直到下一趟开始。
- **休息模式的报告页。** 教练页空闲时，短按 DOWN 打开报告页。短按 UP 回到教练页。

| 字段 | 格式 | 示例 |
| --- | --- | --- |
| 第几趟 | 整数 | 第 3 趟 |
| 滑行距离 | 同实时数据 | 1.9 km |
| 转弯次数 | 整数 | 25 弯 |
| Heygo IQ | 0 至 100 的整数 | 82 |
| 核心问题 | 最多 12 个汉字 | 重心偏后 |
| 小建议 | 最多 20 个汉字 | 下一趟把双手放在身体前方 |

- 报告页上长按 OK 不做任何事。按键提示写"短按 UP 回教练"。
- D-28：手机发送 SHOW_PAGE 时，设备在滑行页或教练页空闲时切换到报告页。在滑行模式中收到时，同时进入休息模式。录音、等回答、播放和退出确认时忽略这条消息，不打断用户。
- 报告页上长按 DOWN 弹出退出确认，与教练页相同。
- 还没有任何报告时，报告页显示"滑完一趟后显示报告"。
- 报告到达 60 秒后，报告页显示"N MIN AGO"。
- 链路中断后，设备继续显示内存中的最后一份报告。

### 数据字段

D-23 由设备团队定义字段。手机应用团队负责计算和发送。每个字段的格式见 07 号文档第 6 节。

| 字段 | 单位与格式 | 实时数据 | 每趟报告 |
| --- | --- | --- | --- |
| 速度 | km/h，整数 | 有 | 无 |
| 落差 | m，整数 | 有 | 无 |
| 滑行距离 | 不足 1,000 m 显示 m，否则显示 km，一位小数 | 有 | 有 |
| 转弯数 | 整数 | 有 | 有 |
| 滑行时间 | 分:秒。满 1 小时显示时:分 | 有 | 无 |
| Heygo IQ | 0 至 100 的整数 | 无 | 有 |
| 核心问题 | 最多 12 个汉字 | 无 | 有 |
| 小建议 | 最多 20 个汉字 | 无 | 有 |

## 8. 成功指标

这些数字是测试目标，不是实测结果。

| 结果 | 目标 |
| --- | --- |
| 连接 | 10 次中至少 9 次在 180 秒内完成。 |
| 提问与停止 | 5 人中至少 4 人戴手套、无人帮助就能提问并停止回答。 |
| 听到回答 | 从松键到第一句可听回答，第 95 百分位不超过 5 秒。 |
| 及时停止 | 松键后 100 ms 内停止采集。取消命令后 200 ms 内停止播放。 |
| 看懂实时数据 | 5 人中至少 4 人在 2 秒内读对速度。 |
| 数据可信 | 缺失的数据从不显示为 0。 |

## 9. 硬件与试用限制

原型使用现有 AI Passport 开发板和可用手机。
已有资料不能证明防水、低温运行、抗风噪或户外可读性。
室内成功不能作为雪场使用能力的证明。
速度和落差的精度取决于手机，设备不做校验。
量产、认证、包装和售后都不在本概念范围内。

# HeygoAI 与 AI Passport：产品需求

版本：0.1。日期：2026-10-16。状态：评审草案。
Product Owner（产品负责人）尚未指定。
本文定义项目概念。
本文不代表联动功能已经实现。

## 1. 产品目标

在休息时，帮助滑雪者完成以下操作：

- 理解一次滑行。
- 选择一个练习目标。
- 交流滑行结果。

HeygoAI 通过待确认的接口提供可用的分析与指导能力。
AI Passport 提供小屏幕、实体按键、麦克风输入和扬声器输出。

最小完整体验包含以下功能：

- 报告。
- 指标图表。
- 弯型回放。
- 一次 Agent 语音交流。
- 一次真人对讲。

这些功能必须围绕同一滑雪会话完成联动演示。

## 2. 用户与使用时机

| 用户 | 需求 | 建议使用时机 |
| --- | --- | --- |
| 休闲滑雪者 | 不打开手机长报告，也能理解结果。 | 一次滑行后的休息时间。 |
| 正在练习技能的滑雪者 | 为下一次滑行选择一个可执行目标。 | 下一次滑行开始前。 |
| 真人教练或同伴 | 与滑雪者讨论某一个弯。 | 双方休息时。 |
| 项目测试者 | 复现交流失败，同时避免泄露录音。 | 室内测试时。 |

试用阶段暂定面向成年人和小型私密群组。
设备形态保持不变。
项目先使用现有开发板完成室内原型。
试用阶段不要求新电路板或新外壳。

## 3. 产品流程

1. 用户通过拟开发的手机配套应用，将设备绑定到账号。
2. 用户手动进入休息模式。
3. 用户选择一次滑雪会话。
4. 设备显示摘要和数据来源。
5. 用户选择一个指标或一个弯。
6. 用户进入教练模式。
7. 用户按住 OK，围绕当前内容提问。
8. Agent 通过文字和语音回答。
9. 用户进入队伍模式。用户与真人教练或同伴对讲。
10. P1 功能可用后，用户可以记录一个练习目标或一条感受。
11. 用户在下一次下滑前退出休息模式。

休息模式表示用户主动确认自己已停下。
已确认的板载传感器不能验证运动状态。
试用阶段只在休息模式中开放报告浏览和语音交流。
休息模式不得声称周围环境安全。

## 4. 范围与优先级

P0 表示拟定最小可用产品，也就是 MVP，必须具备的需求。
P1 表示核心体验完成后的候选需求。
这些优先级属于建议。产品负责人需要在 Sprint Planning 前为待办事项排序。

用户提出的六类能力均保留在 P0：

- 报告。
- 语音输入。
- 语音输出。
- Agent 按键交互。
- 真人对讲。
- 数据和弯型可视化。

离线报告、隐私保护、设备资源限制和明确的模式划分为这些能力提供基础支持。

建议的 P1 功能包括以下内容：

- 单项练习目标。
- 技能任务。
- 练习记录。
- 滑雪会话对比。
- 报告分享。

这些功能必须复用通过检查的数据和现有滑雪会话上下文。
徽章应奖励练习或复盘。不得奖励高速、危险地形，或滑行中持续操作设备。

### 首个 MVP 不包含的内容

- 自动事故检测或救援调度。
- 认证教学、医疗建议，或避免受伤的保证。
- 缺少已验证数据源时，由设备独立测量位置、立刃角或身体姿态。
- 默认持续监听、唤醒词或常开麦克风。
- Agent 语音与真人对讲同时播放。
- 无手机的无线电对讲，或离线传递实时语音。
- 新硬件、商业量产、支付或公开社交网络。

| --- | --- | --- |

| AI Passport 按键 | UP、DOWN、OK 共用一个 ADC 输入。 | 每次只依赖一个按键。 |
| AI Passport 音频 | 已有麦克风、扬声器和 PCM 接口。 | 使用有容量上限的音频流。不能假定有回声消除。 |

以下负责人均指角色，尚未指定具体人员。
验证文档为每个对应的 TC 编号定义完整测试条件。
每行给出用户价值、行为要求、验收目标和主要依赖。

## 7. 体验细节

### 报告与图表

报告首先显示选中的滑雪会话、报告生成时间及距今时长和来源。
同一张卡片最多显示三个摘要指标。
用户选择指标后，可以查看图表和指标定义。
设备隐藏不支持的指标。
设备不得编造数值。

候选指标包括以下数值：

- 时长。
- 距离。
- 弯数。
- 节奏。
- 左右一致性。

实际可用指标取决于真实数据源。
速度、转弯半径、立刃角和身体姿态需要专门的证据与验证。
本文提及这些指标，不代表 HeygoAI 已经提供它们。

### 弯型可视化

报告可以包含实测轨迹、模型估计或示意曲线。
每个视图都必须标明类型。
架构文档定义坐标和方向，防止左右弯显示相反。
缺失的轨迹段必须显示为缺口。

用户可以选择一个弯。
用户可以回放这个弯的现有采样点。
选中的弯会成为 Agent 的交流上下文。
示意曲线可以解释概念。
示意曲线不能支持对用户技术的定量结论。

### 语音与真人对讲

教练模式将语音发送给 Agent。
队伍模式将语音发送到具名的真人房间。
开始采集前，屏幕必须显示接收对象。
同一个长按手势不得同时启动两种交流。

建议的手势从按住 OK 500 毫秒开始。
用户松开 OK 后，设备停止采集。
长按后，应用必须抑制短按事件。
建议单次采集上限为 20 秒。
真人对讲必须先获得发言权限，才能采集或发送音频。

服务器必须先接受 Agent 请求，设备才能开始采集。
服务器接受请求前，设备显示等待状态。
OK 松开或交流取消后，设备拒绝服务器发来的接受通知。

按住 UP 500 毫秒后产生取消命令。
设备必须在识别取消命令后 200 毫秒内停止播放。
这个时限等于从最初按下 UP 起 700 毫秒。
设备必须在识别取消命令后 100 毫秒内停止采集。
正常停止采集的时限从用户松开 OK 时开始计时。

MVP 同一时间只允许一个音频使用者。
它不依赖回声消除能力。
网络中断时，设备停止实时采集。
设备显示网络故障。
连接恢复后，不得补发旧的真人语音。

## 8. 建议成功指标

这些数字是测试目标，不是测量结果或交付承诺。
[验证文档](04-validation-and-decisions.zh_CN.md)定义网络条件和样本数量。

| 结果 | 建议目标 |
| --- | --- |
| 找到报告 | 5 名试用者中至少 4 人无需帮助即可找到指定滑雪会话。 |
| 理解弯型视图 | 5 人中至少 4 人能区分实测数据与示意图。 |
| 收到 Agent 回答 | 从松键到首段可听回答，第 95 百分位不超过 5 秒。 |
| 开始真人对讲 | 获取发言权限的耗时，第 95 百分位不超过 800 毫秒。 |
| 听到真人语音 | 端到端音频延迟，第 95 百分位不超过 500 毫秒。 |
| 保留上下文 | 指定上下文测试中，回答不得对应错误的滑雪会话。 |
| 从故障恢复 | 缓存报告仍可使用。设备不得恢复播放已失效的语音。 |

## 9. 硬件与试用限制

原型使用现有 AI Passport 开发板和可用手机。
团队需要在 Sprint 1 记录设备、手机、托管和语音服务的实际成本。
预算、团队产能、手机平台和试用日期仍待确认。

已检查的资料不能证明防水、低温运行、抗风噪或户外屏幕可读性。
室内成功不能作为雪场使用能力的证明。
户外试用前，团队必须定义使用环境。
团队必须在该环境中测试设备。

商业量产、认证、包装和售后计划不在本次概念范围内。
如果范围扩展到销售，产品负责人必须为这些内容补充独立需求。

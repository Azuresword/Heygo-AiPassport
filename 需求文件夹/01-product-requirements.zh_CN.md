# HeygoAI 与 AI Passport：产品需求

版本：0.4。日期：2026-10-16。状态：评审草案。
产品负责人尚未指定。
本文定义项目概念，不代表联动功能已经实现。

## 1. 产品目标

休息时，滑雪者向 AI 教练询问刚才几趟滑得怎么样，并听到回答。
滑雪者不用拿出手机，也不用摘手套。

HeygoAI 通过待确认的接口提供滑雪分析和教练能力。
手机应用负责语音识别、语音合成和与 HeygoAI 的连接。
AI Passport 提供按键、麦克风、喇叭和一块显示状态的小屏幕。

使用时手机留在口袋里。设备通过手机连网。
所以设备省掉的是"把手机拿出来"，不是手机本身。

## 2. 用户与使用时机

| 用户 | 需求 | 使用时机 |
| --- | --- | --- |
| 休闲滑雪者 | 不看手机长报告，也能理解一趟滑行。 | 一趟滑完后的休息时间。 |
| 正在练习技能的滑雪者 | 下一趟之前得到一条简短建议。 | 下一趟开始前。 |
| 项目测试者 | 复现一次失败的提问。 | 室内测试时。 |

试用阶段面向成年人和小范围群组。
试用使用现有开发板，不需要新电路板或新外壳。

## 3. 产品流程

1. 用户用现有手机应用连接设备。
2. 设备开机后进入滑行模式。滑行模式只显示状态。
3. 用户长按 OK 进入休息模式。休息模式打开后停在教练页。
4. 用户再次长按 OK，提出问题。
5. 用户松开 OK，设备结束本次提问。
6. Agent 用语音回答，屏幕上显示简短文字。
7. 用户可以长按 UP 停止回答。
8. 下一趟开始前，用户长按 DOWN，再短按 OK，返回滑行模式。

休息模式表示用户主动确认自己已经停下。
设备无法检查运动状态。休息模式绝不声称周围环境安全。

| 优先级 | 含义 | 需求 |
| --- | --- | --- |
| P0 | 首版 | REQ-01、REQ-06、REQ-07、REQ-08、REQ-15、REQ-16、REQ-17、REQ-20 |
| P1 | 下一个增量 | REQ-02、REQ-03、REQ-04、REQ-09、REQ-13 |
| P2 | 后续候选 | REQ-10、REQ-11、REQ-12、REQ-18、REQ-19 |
| 延后 | 不在任何已计划的增量里 | REQ-05、REQ-14 |

P0 完整打通一次语音链路：按键、蓝牙链路、手机、Agent、手机、蓝牙链路、喇叭。
每个 P1 功能都复用这条链路。

### 首版不包含的内容

- 报告、图表、弯型视图和真人对讲。它们在 P1 或延后。
- 自动事故检测或救援调度。
- 认证教学、医疗建议或防伤保证。
- 由设备自己测量位置、立刃角或身体姿态。
- 默认持续监听、唤醒词或常开麦克风。
- 不经手机的无线电对讲。
- 新硬件、量产、支付或公开社交网络。
- 蓝牙加密、配对码或绑定校验。
- 隐私与授权功能。

## 5. 能力边界

| 项目 | 证据或状态 | 对产品的影响 |
| --- | --- | --- |
| 屏幕 | 240 × 320。没有证据支持触摸。 | 显示状态和简短文字。 |
| 按键 | UP、DOWN、OK 共用一个 ADC 输入。 | 每次只用一个按键。 |
| 音频 | 有麦克风、喇叭和 PCM 接口。没有回声消除。 | 用小块把声音流式发给手机。绝不边录边放。 |
| 资源 | ESP32-C3、8 MB Flash、无 PSRAM。 | 语音识别、语音合成和 Agent 都不放在设备上。 |
| 电源 | 500 mAh 电池。 | 实测续航，不声称支持全天使用。 |
| 运动与位置 | 没有证据表明有 IMU、GNSS 或气压计。 | 滑雪数据经手机从 HeygoAI 获取。 |
| HeygoAI | 还没有 API 契约和样例数据。 | 由手机应用负责集成。 |
| 手机应用 | 已经存在，由另一个团队开发。 | 设备需求以它的能力为准。[蓝牙协议草案](07-ble-protocol-draft.zh_CN.md)提出了链路方案。 |

## 7. 体验细节

### 教练页

教练页始终显示接收对象：AI 教练。
页面每次只显示一种状态：就绪、正在听、思考中、回答中或失败。
每种状态都同时使用文字和图标，绝不只靠颜色表达。

长按 OK 500 ms 开始采集。设备立即把每一块声音流式发给手机。
设备不等待网关。手机保存问题，直到网关接受。
用户松开 OK 后，设备停止采集，并告诉手机问题已结束。
单个问题最长 20 秒。

手机把回答逐块流式发回设备。设备每收到一块就播放一块。
屏幕可以显示简短的转写或简短的回答。
识别失败时，屏幕请用户重说。
设备不提供转写编辑，因为三个按键无法编辑文字。

### 取消与退出

长按 UP 500 ms，取消当前的采集或播放。
该命令之后 200 ms 内停止播放，100 ms 内停止采集。
从最初按下 UP 到停止出声，总目标为 700 ms。
长按 DOWN 500 ms 弹出退出确认，再短按 OK 返回滑行模式。
长按之后不会再触发短按。

### 音频规则

设备绝不同时录音和播放。
播放期间长按 OK，先停止播放，然后才开启麦克风。
链路中断时，设备停止采集并显示故障。
已取消的回答绝不恢复。

## 8. 成功指标

这些数字是测试目标，不是实测结果。

| 结果 | 目标 |
| --- | --- |
| 连接 | 10 次中至少 9 次在 180 秒内完成。 |
| 提问与停止 | 5 人中至少 4 人戴手套、无人帮助就能提问并停止回答。 |
| 听到回答 | 从松键到第一句可听回答，第 95 百分位不超过 5 秒。 |
| 及时停止 | 松键后 100 ms 内停止采集。取消命令后 200 ms 内停止播放。 |
| 连续使用一小时 | 60 分钟负载下不重启。 |

## 9. 硬件与试用限制

原型使用现有 AI Passport 开发板和可用手机。
已有资料不能证明防水、低温运行、抗风噪或户外可读性。
室内成功不能作为雪场使用能力的证明。
量产、认证、包装和售后都不在本概念范围内。

# Sprint 0：两天计划

版本：0.3。日期：2026-10-16。状态：提案。

本文挑出两天能够做完的工作。
它采用[决策修订](05-decision-amendments.zh_CN.md)中的决策。
它遵循 [Scrum 待办列表](03-scrum-backlog.zh_CN.md)的结构。

两天关不掉任何一个 P0 故事。第 6 节说明原因。
因此本计划命名的是一次技术试验，不是产品增量。

## 1. 当前阻塞了什么

四项依赖阻塞了所有需要外部方配合的故事。团队在两天内清除不掉这些阻塞。

| 阻塞项 | 待确认问题 | 后果 |
| --- | --- | --- |
| 手机应用尚未接受蓝牙协议草案 | Q-13 | 没有真实的流式测试。设备侧工作按 07 号文档进行。 |
| 没有 HeygoAI 的 API 和报告字段 | Q-01、Q-02 | 没有真实报告集成 |
| 语音识别和语音合成服务不明确 | Q-05、Q-13 | 没有真实语音回答 |
| 没有房间服务，也没有第二个终端 | Q-06、Q-13 | 无法测试队伍对讲 |

Q-13 最关键。按 D-14，大部分设备需求取决于手机应用。
D-16 提供了协议草案，因此设备侧工作不必等 Q-13 的答案就能开始。

还有一项限制。AI Passport 开发板不在手边。因此所有设备测试都报告 NOT RUN。

## 2. 两天能做完什么

上面的阻塞有一个共同点。它们挡住的都是需要外部方或开发板的工作。

因此两天瞄准主机测试或固件构建能够检查的工作。
合成数据替代真实报告来源。本地桩程序替代手机应用。

## 3. 两天的划分

**第一天覆盖 T-02 至 T-06、T-09 和 T-10。** 每一项都是纯 C。它们都不触碰 LVGL。
它们都不需要开发板，也不需要手机应用。把握较大。
如果第一天时间不够，T-10 挪到第二天开头，排在延伸任务之前。

**第二天覆盖 T-07 和 T-08。** 这两项都涉及 LVGL 或新工具。把握较小。
计划把第二天单独隔开，这样第二天失败也不影响第一天的成果。

## 4. 任务细节

### T-02：解析报告，并拒绝每一种超限

架构第 5 节列出了上限。解析器必须执行设备负责的每一条上限。
解析器必须拒绝该消息，并返回具名错误。

| 上限 | 取值 | 拒绝行为 |
| --- | --- | --- |
| 控制消息 | 1 KiB | 拒绝，并给出错误类型 |
| 单页报告 | 编码后 8 KiB | 请求下一页 |
| 缓存报告 | 合计 64 KiB | 删除最早的报告 |
| 单弯轨迹 | 128 个点 | 请求保留缺口的简化片段 |
| 并发 Agent 交流 | 1 次 | 先取消上一次交流 |
| 单次采集 | 20 秒 | 停止采集，并释放音频所有者 |

发言人数上限和发言租约由手机和房间服务负责。解析器不检查它们。

解析器还必须执行拒绝过期数据的封装规则。
它必须拒绝过期消息。它必须拒绝旧的设备会话。它必须拒绝旧的连接代次。
它必须拒绝修订号相同但内容不同的报告。

解析器绝不能按消息长度分配缓冲。
随输入增长的重组缓冲违反 REQ-16。

### T-03：生成合成样本集

验证计划列出七类报告。样本集必须全部覆盖。

1. 完整。
2. 局部。
3. 空。
4. 过大。
5. 过期。
6. 损坏。
7. 乱序。

每个样本都必须在数据内容中带 `"synthetic": true`。
每个显示样本的页面都必须显示合成标签。

弯型样本需要已知几何。
样本集必须覆盖左弯、右弯、直线、片段缺口、镜像轨迹和无效坐标系。

### T-04：实现音频所有者状态机

状态机持有一个音频所有者，具有五个取值。
取值为 None、AgentCapture、AgentPlayback、TeamCapture 和 TeamPlayback。

D-11 按页面规定进入采集的条件。

- 在教练页，麦克风在 500 ms 阈值时开启。设备立即发出每一帧。
- 在队伍页，长按会发出发言请求。收到开始消息后，麦克风才开启，设备同时播放提示音。

D-10 规定取消路径。长按 UP 取消当前音频所有者。长按 DOWN 返回上一页。

生成的测试必须覆盖每一条转移。它还必须覆盖以下路径：

1. 用户在队伍开始消息到达前松开 OK。设备忽略迟到的开始消息。
2. 用户在教练采集期间取消。设备向手机发送取消消息。
3. 用户在播放期间取消。设备丢弃之后到达的每一帧。
4. 链路在采集或播放期间中断。
5. 手机报告识别失败。
6. 用户在 Agent 播放期间长按 OK。播放先停止，麦克风再开启。

这些测试由本地桩程序扮演手机。桩程序不能证明真实的手机接口。
状态机使用蓝牙协议草案中的消息名称。

### T-05：实现休息模式门禁

门禁遵循 D-15。

主机测试必须证明以下规则：

- 滑行模式阻止每一种语音操作。
- 在滑行模式中长按 OK，进入休息模式，并停在报告页。
- 用来进入休息模式的那次长按不会启动采集。
- 退出休息模式时，停止每一个音频所有者。

### T-06：实现弯型几何契约

架构第 4 节定义了坐标系。原点位于本弯第一个有效采样点。
`y` 轴正方向沿参考下坡方向。滑雪者面向该方向时，`x` 轴正方向朝右。

航向角等于 `atan2(dx, dy)`，单位为度。从下坡方向顺时针旋转时航向角为正。
展开后的航向角变化为正表示右转。展开后的航向角变化为负表示左转。

实现必须依据航向角变化判断方向。
它绝不能依据曲线在屏幕上的位置判断方向。一项主机测试必须用镜像样本证明这一点。

### T-09：实现 IMA ADPCM 编码器和解码器

D-09 选定 16 kHz、单声道、每帧 20 ms 的 IMA ADPCM。一帧包含 320 个采样。
每一帧开头都带自己的预测值和步长索引。
因此丢失一帧不会破坏下一帧。

主机测试必须证明以下规则：

- 一块 320 个采样按 07 号文档的格式编码后正好 164 字节。
- 解码后的 1 kHz 正弦波信噪比高于 20 dB。这个阈值是初始值。
- 丢失一帧后，解码器能正确读取下一帧。
- 满幅输入不会造成整数溢出。

编解码器是纯 C，不依赖 ESP-IDF 或 LVGL。
块格式和包头由蓝牙协议草案规定。

### T-10：实现蓝牙协议草案的包层

包层负责组装和解析[蓝牙协议草案](07-ble-protocol-draft.zh_CN.md)中的包。
它是纯 C，不依赖 NimBLE、ESP-IDF 或 LVGL。

主机测试必须证明以下规则：

- 每种消息类型组包后再解包，字段保持一致。
- 长度错误的包被拒绝，并给出错误码 2。
- 未知类型得到错误码 1 的回复。
- 载荷末尾多出的字节被忽略。
- `xid` 过期的音频包和状态包，设备一律丢弃。
- 报告分片能重组成一页。分片序号跳号得到结果 2。总长度超过 8,192 字节得到结果 1。

包层不能证明真实的手机链路。Q-13 保持开放。

### T-08：生成中文字体子集

主机没有 `node`，因此 `lv_font_conv` 无法运行。一次检查找到了可用的替代方案。
Pillow 11.3.0 报告 `freetype2: True`，并成功栅格化了 20 px 的 `休息模式`。

因此本任务改写一个 Python 生成器。生成器读取产品词汇表。
它只栅格化词汇表需要的字形。它输出 `lv_font_t` C 数组。

覆盖检查必须列出每一个缺失字形。
构建成功不能证明字形覆盖。上游基线对这个陷阱提出过警告。

## 6. 本切片的完成定义

项目的完成定义要求设备测试和真实服务。本切片两项都不满足。
因此本切片报告的是技术试验结果。

下列每一条都成立时，本切片通过。

- 固件构建通过。
- 主机测试通过。
- 仓库检查通过。
- 每份新增英文文档的结构检查报告零违规。
- 每份新增中文文档与其英文配对一致。
- 每个合成页面都显示合成标签。
- 报告记录实测静态内存和 Flash 大小。

本切片按要求的格式报告结果。

```text
Build: PASS / FAIL / NOT RUN
Host tests: PASS / FAIL / NOT RUN
Device tests: NOT RUN
Unverified: 全部外部服务、全部设备行为、全部现场条件
```

本计划中没有任何任务关闭 P0 故事。第 5 节和第 1 节列出了缺失的证据。
